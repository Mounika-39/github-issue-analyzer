Three steps

1

Paste a repository link or type owner/repo on the Home page.

2

The IssueCount server asks GitHub for the issue list and keeps the result for a few minutes, so repeat lookups are instant.

3

The page shows the counts, a health score and charts. Download them as CSV or PDF.

What gets counted

  • Issues that are open or closed. Pull requests are left out.
  • Average days to close, measured from opening to closing, for closed issues only.
  • The top 10 labels and assignees, and issues opened and closed per month.
  • With a label filter, only issues carrying that label.

Health score and trends

The health score blends how many open issues are stale (no activity for 90 days), how many open issues have an assignee, and how many issues are closed.

Every time a repository is looked up, the server saves one snapshot per day. The trend chart draws those snapshots, so it grows the more the repo is checked.

Rate limits and large repos

GitHub limits how often it can be asked for data. IssueCount keeps its own copy of recent results, and if GitHub refuses a request it shows the last saved result and says so.

Very large repositories hit a GitHub paging limit. The page tells you when the counts are partial.

About IssueCount

IssueCount is a full-stack project that turns a repository's issue list into numbers you can read at a glance: how many issues exist, how many are still open, how long fixes take, how healthy the backlog looks, and how it changes over time.
